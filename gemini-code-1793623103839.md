## 2. Architecture & Module Design

The codebase relies entirely on browser-native ES6 modules (`type="module"`), eliminating bundlers, build tools, and third-party dependencies.

- **`js/state.js`**: Defines the central `state` singleton. Normalizes raw API input so that `height` and `weight` metrics are cleanly mapped to standardized numerical units (`cm` and `kg`). String zeroes (`0 cm`, `0 kg`) and empty dashes are normalized to `null`.
- **`js/filterSort.js`**: Contains pure transformation algorithms. Enforces that missing values (`null`, `""`, `undefined`) are pushed to the bottom of the table on both ascending and descending sorts.
- **`js/render.js`**: Handles inner DOM construction. Slices data based on active pagination parameters and attaches data attributes for row selection.
- **`js/dossierUrl.js`**: Manages modal presentation and mirrors all active states (search query `q`, vector `f`, operator `op`, sort column `sc`, sort direction `sd`, page `p`, page size `size`, and hero ID `hero`) into the browser URL via `window.history.replaceState`.
- **`js/app.js`**: Top-level coordinator that wires DOM listeners to the imported state and functional handlers.

## 3. Local Development Instructions

Because ES6 modules are subject to browser CORS policies when run directly via the `file://` protocol, the application must be served using an HTTP server.

# Run local HTTP server
